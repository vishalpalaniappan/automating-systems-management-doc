The Design Abstraction Language (DAL) itself is just a structure that can be used to construct the meaning of a design. I've written a basic AST library that can be used to establish blocks and commands with arguments, this is sufficient for now. Its the structures that are built with this that define the meaning.

Note: Since the design will be machine generated by constructing it from the artha script, I can just use JSON and then access the necessary information that I need. I will modify this section later but for now this note will be sufficient.
\subsubsection{Structure}

The structural specification enables the the construction of a block using braces. For example, the block can be used as follows to specify control flow logic for a behavior.

\begin{minted}[linenos, frame=lines, mathescape]{python}
select {
   # Specify control flow logic
}
\end{minted}

\subsubsection{Commands or Attributes}

The command structure itself is specified as shown below. Each command is specified and in the bracket the arguments are provided. There can be keyword commands used by the design and then there are custom commands that reference more meaning.

\begin{minted}[linenos, frame=lines, mathescape]{python}
# Built In
design("Design Name")

# Custom Command
command(
    number=123, 
    string="String", 
    arrayArg=[12,33,12], 
    objArg={"a":1}
)

# Reusing structure to specify attributes
property(
    name="type"
    description="Data type of participant (list, object, str etc)"
    type="string"
    get="getType"
)
\end{minted}

\subsubsection{Control Flow}

The control flow structure itself is specified as specified below. Currently, only if statements are supposed but not else if or else blocks. I need to extend the library to support this.

\begin{minted}[linenos, frame=lines, mathescape]{python}

# Currently supported
if (boolean) {
    
}
\end{minted}

This basic structure makes it possible to specify all the necessary attributes without making the AST implementation itself complicated. As I work through the reasoning and build the CSM, I will be using these structures specify the necessary meaning. If I run into features I can't support, I will return here and add to it. 

\subsubsection{Abstract Syntax Tree}

The DAL script is parsed into an Abstract Syntax Tree(AST) that is then used by the validator. An example of a simple AST generated by a DAL script is provided below. In a full design specification, multiple dal files can be used to specify the behavior attributes, participant attributes etc. 

\subsubsection{Sample DAL Script}
\begin{minted}[linenos, frame=lines, mathescape]{python}
design("test")

behavior getName {
   select {
      goToBehavior(addBook)
   }
}

behavior addBook {
   #...
   select {
      goToBehavior(getName)
   }
}

\end{minted}
